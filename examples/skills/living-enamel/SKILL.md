# Living Enamel

Make the film the user asked for in this material language: raised rounded gold wire, jewel-coloured glossy enamel, cabochon eyes, riveted rigid characters, and a travelling studio light. The picture tells the story through objects being poured, moved, assembled, stamped, cracked or replaced. Use the supplied renderer rather than generated still-image slides.

## Story first

Before choosing a topic or hook, read `series-card.md` in the film folder's parent if present. Follow its audience promise, title pattern, first-frame rule and ending rule. Read any `analytics.csv` beside that card or in the film's parent; compare snapshots of similar age and name **one hypothesis** this film tests. If there is no data, label it an untested hypothesis, not an audience finding. Create the CSV with the [ledger header](references/story-records.md#analytics-ledger) when a series card exists and no ledger does.

Before any drawing or voice work, write `story-card.md` in the film folder. Record the person (or, for a true mechanism story, the causal problem), what they want, who or what opposes or doubts them, what the viewer expects, what the sources say actually happened, the final image that overturns that expectation, and one sentence a viewer might repeat or argue with. **Write the final image before the middle.** Never invent motives, dialogue-as-fact, deaths or outcomes to make history fit. Label every dramatisation beyond the sources in the card and delivery note; attach a source to **each factual narration claim** in the card. Label fiction as fiction. Use the [card outline](references/story-records.md#story-card) to keep those decisions reviewable.

Write three opening sentence + frame-zero pairs from the **same facts**: a strange act by a person in mid-action, a contradiction, and a personal stake. For each, record “viewer expects X, stays to learn Y”; choose one with a written reason. The first sentence describes a person doing something, not a date, topic label or fact already complete in itself. A true mechanism story still opens on a sourced human action using or encountering it, without inventing a protagonist or motive. No year in the opening sentence or title unless the year itself is the surprise. Frame zero shows that act already under way with the key prop large.

Reward early, then earn every remaining second with a **new consequence**. Mark the early reward and the time the viewer first knows the answer to the opening question. If nothing changes after that answer, cut there or open a second real question; do not hide all useful information until an obligatory last-line twist. Establish opposition, doubt or a causal obstacle within 3–5 seconds, then escalate through sourced consequences. Plan an information-changing visual beat about every 2–3 seconds: a new prop, reaction, reveal, cutaway or reframing, without requiring a hard cut. Keep the key object recognisably the same object from setup to payoff.

Choose the length profile and put a plain `ending_mode: loop`, `ending_mode: punchline` or `ending_mode: consequence` line in the card, with the reason below it. `feed` defaults to a loop; `story` defaults to a consequence. A loop line must add meaning, not restate the opening fact. A punchline or consequence ends on a visible outcome that changes what the opening meant, not a summary of the mechanism. An alternate ending for a feed film needs a recorded feed exception if it fails the retained loop check.

## Start a project

Import this entire skill folder. Run `python <skill>/kit/setup.py <workspace>/film` using an available Python. Setup selects Python 3.11–3.13, copies the toolkit without overwriting creative work, creates `film/.venv`, installs dependencies and checks FFmpeg. It reuses cached Kokoro weights or downloads the public weights on first setup. Use `--python <exe>` or `--models <folder>` when needed. All further commands run with the printed venv Python from `film/`.

Read [authoring](references/authoring.md) for the drawing/shot API and narration schema; [cast](references/cast.md) for included character rigs; [worlds](references/worlds.md) for places via `from stories import world as W`; and [sets](references/sets.md) for compatible Byzantine pilot scenery and props. `example/feed-pyramid.py` and its JSON demonstrate bright framing and loop mechanics with estimated 18s timings, not the new story-first writing standard. The bust (`example/story.py`) and court fable (`example/king-tomorrow.py`) demonstrate materials and landscape staging. Reuse their techniques, not their scripts as substitutes for the requested film. No example is a validated 45–65s story template.

Use the brief or infer ordinary creative choices and proceed. Historical claims need sources; label an original fable as fiction. Keep a narration/script file and source scenes in the project. Reuse materials and rig parts, but author shot-specific objects and actions. Do not substitute the example movie for a new request.

To test a fresh feed kit, copy `example/feed-pyramid.py` and `example/feed-pyramid.json` to `story.py` and `script.json` in `film/`, then run the production sequence below. Test the longer example in a separate working folder, copying `example/king-tomorrow.py` and `example/king-tomorrow.json` to those names so its timeline cannot replace another film's.

## Hold the opening

For a short vertical feed film (Shorts, Reels or TikTok), frame one is the hook. The viewer makes the swipe decision before a setting or title can explain itself. Design the first encoded frame and its first two seconds before expanding the film. Landscape and long-form work keep clear subjects and consequential action, with pacing and titles adapted to their brief.

- **Show the chosen act and prop, large.** One dominant subject fills the frame, usually at least about 60% of its width or height, recognisable at 270 pixels wide. Its surprising action is already under way on frame 0 and continues visibly: a casing changing, a coin landing, an object being taken. Camera drift, glints and smoke around an otherwise finished picture do not carry the claim. No fade-in.
- **Use a bright, simple, saturated place.** No black ground, dark vignette or ornate border at the hook. Bright sky with the real location around the subject is the usual answer; it does not waive “Build the world.” `W.sky(..., mode='bright')` removes the vignette and brightens enamel while retaining gold wire and material light. Add the actual terrain, architecture and continuous floor.
- **Put the promise on frame 0.** Use 3–6 words, all caps, heavy sans-serif, in two or three lines spanning roughly 80% of the width. Capitals should be about 110px or taller at 1080x1920, with a dark outline or plate. Withhold the mechanism. Keep text clear of the top 8%, bottom 20%, right-hand 12% and the prop's key feature. It is fully readable immediately, stays about two seconds, then goes. No opening title plaque or date card. `Film(..., hook=Hook(('HE OPENS','THE LOCKED BOX'), return_span=0))` supplies the screen-fixed layer; omit `return_span=0` only for a loop ending.
- **Caption for the profile.** Feed keeps heavy sans capitals about 92px high, two or three words at a time. Story uses burned-in bold white with a dark outline, 1–4 words at a time in the lower-middle (about 70% down), with glyph height about 3–3.5% of frame height (64px at 1920). Both follow speech timing; correct estimated word anchors when needed. The hook suppresses duplicate captions while visible. Inspect actual 270px frames: nominal font size is not delivered glyph height.

After preparing the real narration, make an opening sheet and a moving draft. `--opening` includes six 0–3s samples, the last/first picture pair and a `.feed.json` report; `--strict-feed` fails unwaived measured checks. Inspect the first frame itself, the place, text clearance and substantial progress between samples. A sheet can miss a pause between them.

```text
<py> -m gilt sheet story.py --format portrait --scale .5 --opening --strict-feed --out work/opening-sheet.jpg
<py> -m gilt still story.py --format portrait --t 0 --out work/frame-0.png
```

Judge stayed-to-watch alongside viewing duration among those who stayed. Low feed acceptance with strong viewing or replay among retained viewers suggests testing a stronger premise/opening while preserving what engaged them; it does not prove a cause or guarantee wider distribution. Use owner-supplied analytics, not old aggregate percentages as universal targets.

## Choose the length and ending

Set `"profile": "feed"` or `"profile": "story"` explicitly in `script.json` (or use `prepare --profile ...`, which stores the choice in the timeline). Never infer the profile from length.

- **feed:** 15–20 seconds, aiming for 17–19. Establish the opening promise within about two seconds with a first sentence of about seven words at most. Give an early reward by the middle, then a new consequence or meaningful loop; end sooner if the complete answer leaves nothing to change.
- **story:** 45–65 seconds, narration **2.9–3.4 words per second** measured over the **whole film**, including pauses: about **160–185 words for 55s**. Use fewer words and real breathing beats, not a TTS speed change alone. Name at most **three people**; give everyone else a role such as “the guard” or “the clerk”. Put one idea in each sentence and use short, plain words. Establish the opening promise by 5s (the first-sentence timing tripwire allows up to 5.5s, without a seven-word cap). Use this length **only for stories with enough steps**; never stretch a 25-second premise. End on the consequence, with no branded outro or spoken like/subscribe request.

For **story**, leave at least **two narration-silent gaps of .7s or more**: one immediately after the turn (the reveal/twist sentence), and one before the final line. Give those beats to picture and sound: an action, reaction or sound effect fills the pause, not dead air. Put `"pause_after": 0.8` on the turn's clause and on the clause just before the final line; `prepare` inserts silence after those separate synthesized blocks, including with Gemini. Keep the final beat within the last 8s. See the [sentence-block example](references/authoring.md#story-breathing-beats). QA measures word gaps; its proxy requires two gaps ≥.7s, one starting within the last 8s, and cannot identify the turn or final line semantically. Check their placement in the story card and moving draft.

Narration starts by .1s for **feed**, by .5s for **story**. After the card, generate the actual narration before accepting timings or expanding the drawings; measure voice and cut words to fit, never change tempo to force duration. Both explicit profiles supply .04s lead, short default gaps and .08s end hold unless scripted, with at most .15s end hold; story needs the two longer scripted beats above. The legacy `--feed-short` / `"feed_short": true` still works. Keep the first sentence in its own voice clause for the timing check.

For `loop`, join last and first lines grammatically with changed meaning and return the last picture to the opening pose, place, light and text. `loop_return` targets the last encoded frame; keep acting through the approach. Inspect the last/first pair and audio join: pixel similarity cannot prove a natural spoken loop. For `punchline` or `consequence`, omit `loop_return` and set `Hook(..., return_span=0)` so the opening text does not cover the outcome. No end card, fade or empty tail.

## Build the world

A person on a coloured ground tells us what they look like, but gives us little reason to believe the event. Every shot needs a place: the viewer should sense where we are, when, and who else is here before reading a label. A close shot needs a room around the face just as a wide shot needs a landscape.

- **Research the place with the event.** For history, look up that region's architecture, dress and working objects at the stated date before drawing. Keep source links and distinguish documented features from reconstruction. A surviving palace may have later additions; a painting may show a different reign. Do not furnish a Sikh court with a European throne or replace a Sahelian city with domes because those are the available assets.
- **Compose a world, not a border.** Use the [world kit](references/worlds.md) for sky/light, land/water, regional exteriors, interiors and background people. Select the pieces that describe this place, then author the distinguishing building, tool or costume yourself when the kit lacks it. A patterned ground, a date plaque and a few floating architectural lines do not locate a character.
- **Give the eye distances.** Separate far scenery, the inhabited middle distance and a near floor, jamb or table through value, detail and scale. Use restrained `Camera` movement with `p.layer(depth)` so the layers shift against each other. Keep touching actors, chairs and floors on a common contact plane; parallax should reveal space without making feet slide.
- **Let the place live.** Pass local time to clouds, flags, water, lamps or supporting people that belong here. Choose a few appropriate movements rather than animating every ornament. Ambient life gives a room or landscape continuity; it does not perform the main story action. Declare the place's ambience and acted sounds as described below.
- **Carry the place through the frame.** Extend the floor, carpet, shore or foreground table behind the caption band and to the bottom of the portrait crop. Keep this area quieter for reading, with perspective and material continuity. An empty lower third is not caption clearance.
- **Protect the subject through hierarchy.** Keep the key face or prop large, bright and legible against broad scenery with thinner contours: bright and saturated for a feed hook, deep jewel-coloured scenery elsewhere. Preserve saturated enamel colour; separate subject and setting through value, scale and detail. Reduce competing detail around its silhouette instead of removing the room. Inspect a full-size still and a roughly 270-pixel-wide view: can you name the kind of place, see its period cues and follow the important action?

Normal `gilt sheet` now prints bare-stage warnings, marks the sheet and writes a sibling `.world.json` with samples from every shot. Read it with the images and repair empty stages before rendering. `gilt world-check story.py --out work/world.json` runs the warning separately; add `--strict` to fail on unwaived warnings. A deliberate map, extreme close-up or open landscape can state its reason with `Shot(..., world_exception='Map: schematic transfer route')`. The raw warning stays visible. Flat-colour measurements cannot recognize historical accuracy or a convincing place, and ornament can fool them; a passing number never substitutes for looking.

## Keep every scene moving

The opening earns a look; each later thought must earn the next one. A jewel on a pedestal stops giving the viewer something to watch once its reveal is understood. Plan the performance against the prepared narration, not just the shot boundaries.

- **Give each thought an action and a consequence.** For every narration thought, note what starts moving, what changes when the words land, and what carries the eye into the next thought. A figure offering a prop, visitors turning and leaving, a grinding wheel working down a stone, an advancing route or an enamel state changing can carry a sentence. Give each narration clause its own large action or a clearly different framing. One view held for many seconds reads as a still picture even when a pendulum or smoke keeps the motion check passing. Keep progress legible at phone size; an action too small to notice cannot carry the scene.
- **Keep something acted in motion.** A prop or figure doing something tied to the narration counts. So does a camera travelling through a scene to reveal new relationships, or a state visibly changing. A uniform zoom over a completed composition, glints, drifting light, waving flags or background bustle alone do not advance the thought. Ambient life supports the performance; it does not replace it.
- **Let a beat land, then give the eye its next task.** A brief settle can make an impact readable. Once the consequence is understood, start the next gesture, reveal or journey rather than holding a finished picture under the rest of the sentence. In a 15–20 second feed Short, around a second can already feel empty; more than two seconds without sizeable change is a repair signal, not an allowance to insert a token twitch every two seconds. A deliberate held reaction needs a reason worth the viewer's time and an explicit QA waiver.
- **Review the middle and the ending too.** Check half-second samples through every thought, then the moving draft. Look for progress, not merely different lighting. The encoded movement check catches long local-change gaps; it cannot decide whether a crowd is acting out this story or merely moving behind a stationary hero. Repair the performance even if its numbers pass.

## Optional Gemini narration

When `GEMINI_API_KEY` is present and neither the user nor Moco's project preference chose another voice, use `film.py prepare script.json --engine gemini` (optional `--gemini-voice Charon --style "dryly amused"`); the portable `audio/gemini_tts.py` helper uses the user's billed Google account. Otherwise keep the current Kokoro voice; uploaded narration always wins: preserve the recording and its timing rather than running synthesis. Put delivery direction only in `--style` (or script `style`), never in `spoken`; the selected voice defaults to `MOCO_GEMINI_TTS_VOICE`, then Charon. The same per-clause trim, 48 kHz resampling, cache, estimated word timings and review steps apply; change the script's `engine` to `gemini` to keep that choice for later prepares. With Gemini, set up a fresh kit with `--no-tts` to skip local voice weights; no new Python dependency is needed. A missing key stops with a clear fallback message; use the current local voice or an upload instead. Never print the key or inspect the environment to display it.

## Keep the voice in front

The narrator carries the story on a phone speaker. `mix` levels the voice first, then measures the music and the whole effects bus, including ambience, against it. During speech, music stays at least 18 LU below the voice, effects and ambience together at least 12 LU below, and their sum at least 10 LU below, in overlapping 100/400 ms windows in stereo and mono. Quiet consonants count; numerical silence does not. The background is down before each phrase, with extra clearance around the opening word. The mixer guarantees these measured margins, so do not leave actions silent to protect the voice. These limits cannot prove that a particular word is understood.

- **Every visible action gets its sound; every sound has a visible cause.** Declare the accent when the object strikes, breaks or lands, footsteps when feet contact, cloth when a sleeve moves, and a working texture for the whole wheel/contact action. Use variants for repeated contacts, timed to the pictured action. Do not run an unrelated repeating timer under a sentence or add an impact to a motionless object. Sustained travel or grinding needs a texture or a sequence that follows its actual progress, not one tiny cue at the start and silence thereafter.
- **Give every place its ambience.** Declare a quiet continuous bed for the hall, sea, workshop, market, desert, fire, rain or distant battle shown. Use `p.ambience(0, 'hall', ctx.shot.end-ctx.shot.start)` for a whole shot, or give a local start and duration for a smaller range. The mixer loops with overlapping joins, fades and crossfades range edges, and includes all overlapping beds inside the effects and combined-background limits. Music is not the sound of a place. Choose a bed that belongs to the pictured world; a schematic transfer map can use a restrained designed texture, without implying a historically verified sea route.
- **Leave the hook's first words clear.** Let narration establish the stake before adding a busy sound sequence. The mixer anticipates speech and protects the opening word automatically; it cannot decide whether an accent distracts from the hook. Check the first line against the script with a local word check when available, and listen when possible.
- **Put strong accents at thought boundaries.** Prefer a phrase end or a gap for a crash or impact, so it punctuates the visible event without competing with a name or key claim. In gaps, effects can rise toward 6 LU below the leveled voice's integrated reference; speech protection always takes priority over an accent.
- **Use gain for emphasis within the budget.** `p.sound(time, name, gain=1)` uses 1 for the standard accent, .5 for half its amplitude (about 6 dB lower), and 0 for silence. Values are clamped to 0..1 and recorded. Gain does not set an absolute volume or defeat ducking; move or remove a competing cue instead of asking for more gain.

`mix` targets -14 LUFS with the voice alone within .5 LU of the master, reserves PCM peak headroom at -2 dBTP, and checks a local AAC encode against -0.8 dBTP. It writes `work/balance-report.json` with voice loudness, speech margins, the worst window and overlapping events, and clamped gains. Read it before encoding. A failed mix stops; repair the voice or cue pattern and rebuild. For an intentional exception, `film.py mix --allow-balance-override "reason"` records the reason and failed checks. Disclose that waiver; it is not a passing balance result, and encoded loudness/peak QA still applies.

## Produce the film

Write `script.json` and `story.py` inside `film/`, after the card. Match narration scene IDs to `Shot.id`. Use the real narration timeline to drive actions. Commands show a feed Short and both cuts; run only the requested formats. For story, use `prepare script.json --profile story`; rendering/opening sheets read the prepared profile. For layout-only estimates, set `Film(..., profile='story')` too. Draft `publish.md` before strict checks, then replace pending duration/hash with the final encode's values before final QA. Landscape skips the portrait profile. Other portrait briefs can use `--allow-feed-exception "reason"`, retaining raw failures and all other checks.

```text
<py> film.py prepare script.json --profile feed
<py> -m gilt sheet story.py --format portrait --scale .5 --opening --strict-feed --out work/opening-sheet.jpg
<py> -m gilt sheet story.py --format portrait --scale .5 --n 12 --out work/portrait-sheet.jpg
<py> -m gilt sheet story.py --format landscape --scale .5 --n 12 --out work/landscape-sheet.jpg
<py> -m gilt world-check story.py --format portrait --strict --out work/world-portrait.json
<py> -m gilt world-check story.py --format landscape --strict --out work/world-landscape.json
<py> film.py events story.py
<py> film.py mix
<py> -m gilt clip story.py --format portrait --scale .5 --start 0 --end 3 --audio work/mix.wav --jobs 2 --out work/opening-draft.mp4
```

Open the sheets for each requested cut and representative full-size stills with an image-capable tool. If that tool is unavailable, deliver the sheets, use concrete user/host visual feedback and report the limit; rendering a sheet or reading its dimensions does not establish visual inspection. Inspect action extremes, text and faces, and hold the opening sheet and motion draft to the opening, world and movement rules above; fix overlaps and weak framing. Snap rigid parts about their rivets using `tick`; avoid long floaty transformations.

For a shared layout, essential action belongs inside x/y 0..1080; portrait adds top/bottom and landscape adds sides. Keep essential portrait action clear of the two-line caption clearance at stage y=920..1210. Extend grounds through both crops. Inspect each requested composition independently: a successful portrait crop does not establish good landscape framing. Use format-aware staging or artwork transforms when the shared layout leaves subjects small or large areas filled only with ornament. Phone captions and hook type stay fixed on screen, outside shot-camera transforms. Captions are automatic in portrait, absent in landscape; author a running landscape caption if useful. Landscape and long-form can retain their authored plaque treatment.

After checking drawings, render the requested formats (30 fps; full scale is 1080x1920 or 1920x1080). Use `--jobs 2` on a machine with 15GB RAM; more workers need measured memory headroom. A shorter or lower-resolution draft is useful during iteration, but disclose its resolution when delivered.

```text
<py> -m gilt render story.py --format portrait --audio work/mix.wav --jobs 2 --out out/film-portrait.mp4
<py> -m gilt render story.py --format landscape --audio work/mix.wav --jobs 2 --out out/film-landscape.mp4
<py> film.py qa --story story.py out/film-portrait.mp4 out/film-landscape.mp4
```

Declare sounds every call to a drawing function, e.g. `p.sound(ctx.cue(1), 'clink')`, rather than in a narrow frame-time condition. `events` gathers these declarations before the music/mix. After narration or event changes, regenerate events and mix before the final encode. Read the voice-first balance report; the mixer places all cues inside the speech budget and targets -14 LUFS rather than normalizing a busy background into the voice's place. Drawing-only revisions can reuse narration. For an effects/balance-only remix of an existing MP4, preserve `narration.wav`, `timeline.json` and the authored `music.wav`: run `audio/sfx.py`, `film.py events story.py`, then `audio/mix.py` directly. `prepare` regenerates voice; `film.py mix` regenerates music and may change its shatter cutoff. Put the new mix on the existing picture with FFmpeg video stream copy; fresh animation needs rendering again.

## Verify and deliver

`events` prints per-shot one-shot counts and ambience range coverage and writes `work/coverage-report.json`. Read its warnings before mixing: no sound, ambience only, and missing beds need an author decision. Declare cues unconditionally, regenerate events after timing changes, and keep the generated `work/sound-shots.json` with the timeline so QA can name the shots.

`qa` decodes the actual files and checks audio/video duration, format/rate, -14 LUFS loudness (within .5 LU), encoded true peak at or below -0.8 dBTP and black/frozen stretches. It retains the opening's sustained-change-by-1s requirement and measures local picture change throughout each shot at .1s intervals over .3s comparisons, discounting lighting, captions and uniform camera drift. Two consecutive qualifying observations establish change; a gap longer than two seconds fails with its shot and time range. Authored shot cuts do not count as action. It writes `.motion.json`, `.coverage.json`, whole-film contacts and a six-frame encoded opening strip (`.opening.jpg`, 0–3s). Coverage fails a shot with confirmed movement and no nonzero sound at all; missing/partial ambience, ambience-only action and moving ranges without nearby foley warn with details. A bed or a nearby cue does not prove that the action has its right sound. Inspect every warning, including shots where small motion escaped measurement.

Portrait QA reports the chosen profile: `--profile` overrides the prepared timeline's `profile`; absent both, legacy `feed` limits apply even above 20s. Feed retains today's timing, hook, bright-background and endpoint-similarity checks. Story checks 45–65s, lead <=.5s, first sentence <=5.5s, end hold <=.15s, stored narration / encoded duration at **2.9–3.4 words/s**, **at least two internal word gaps ≥.7s, one starting in the last 8s**, nonempty `story-card.md` and `publish.md`, and a declared ending mode. Opening lead and trailing hold do not count as breathing beats; missing word anchors fail. Story keeps hook/brightness and first-second movement requirements; endpoint similarity applies only to `loop`. `--story story.py` supplies the expected `Hook`; declaration alone cannot pass pixels. QA writes `.feed.json`, decoded boundary frames and `.loop.jpg` (a boundary pair, even for non-loops). Missing evidence fails. Existing feed, still-opening/shot and balance waivers retain raw failures and their reasons.

Check a story encode with `<py> film.py qa --profile story --story story.py out/film-portrait.mp4`. For the profile plus first-second movement alone, use `<py> -m gilt.feedcheck out/film-portrait.mp4 --profile story --story story.py --out work/story-profile.json`; this never synthesizes speech and does not replace full QA. These checks verify timing, pixels and **file presence, not whether the story is good**, claims are sourced or publishing text is complete. Brightness cannot identify a place; estimated timing cannot prove spoken timing; pixel matching cannot establish recognisability, payoff, grammar or a seamless audio join.

QA also surfaces `work/balance-report.json`, checks that its source stems/cues, ambience and mix are current, and compares decoded audio with that mix to catch stale encodes. A waveform match tolerates AAC loss and is not an identity proof. For a deliberately still opening, `qa --allow-still-opening <files>` records a waiver. For a deliberate later hold, use `qa --allow-still-shot "crown=reason for this held reaction" <files>`; repeat for another shot. The hold remains listed with its reason, and decode, freeze, sound and balance checks still apply. Do not waive a weak scene to make delivery pass.

Resolve failures at the source and render/verify again. Measurements cannot prove meaningful acting, readability, intelligibility, appropriate sound or factual accuracy. Thin wheels, small/slow gestures, fast periodic motion, pure camera travel and masked action can be missed; moving scenery or within-shot cuts can pass. Open the whole-film sheets and inspect motion through every scene, not only the hook. Listen if a listening tool is available; otherwise state plainly that sound was measured and not listened to. Do not describe how it sounds or claim playback/listening review from technical checks alone.

Complete `publish.md` in the film folder: a proposed title naming the strange object or act while withholding the mechanism, about six words, no year (unless the year is the surprise), hashtags or emoji; a two-sentence description with source links; one optional pinned comment posing a real two-sided judgement about this story, never “comment YES”; and each final MP4's measured duration and SHA-256. Include the fact/fiction and dramatisation note. This is a draft handoff, not permission to upload or publish.

After delivery, append a row to an existing parent `analytics.csv` (or the ledger created for the series), using the [exact schema](references/story-records.md#analytics-ledger). Record folder, final file hash, active `SKILL.md` hash, topic, hook sentence, first-frame description, voice, duration, narration words and ending mode. Leave upload date, snapshot age, shown in feed, stayed %, views, engaged views, average % viewed, average duration, likes, comments, shares and subscribers gained blank for the owner; unknown is blank, never zero. Preserve earlier rows and compare matching snapshot ages next time.

Copy final movies, contact sheets and `publish.md` to the Moco workspace's `outbox/`, and deliver with its available file tool (`moco_SendUserFile` or `mcp__moco__SendUserFile`). Report duration, dimensions, fiction/fact and dramatisation status, actual voice/engine, QA results and craft limitations. Keep the card, editable sources and reports in the project. Rendering is local; optional Gemini narration is billed, and the hosting agent uses the user's chosen AI access. Respect any user restriction on generation or publication.
