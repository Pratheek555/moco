# Architecture reference

Moco hosts a user's skill in a persistent desktop conversation. It adds no content pipeline or creative decisions.

## Provider and session

`packages/agent/src/types.ts` defines `AgentProvider`, `AgentSession`, and typed events for text, thinking, tools/results, tasks/background activity, questions/answers, permissions, file delivery, errors, usage and turn end. `send()` accepts messages while the session is running. `interrupt()` interrupts a turn; `stop()` closes the process and pending callbacks. The app's Stop uses `stop()` so background work and waiting questions are cancelled too.

`claude.ts` uses the [Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/typescript), with an asynchronous input stream, partial messages and `resume`. It resolves the installed Claude Code executable without shell interpolation (including native Windows installs and npm's Windows JS entry). It checks `claude auth status` for a Claude subscription. It strips inherited Anthropic credentials, endpoint overrides, OAuth token overrides and cloud-provider switches. There is no API-key configuration or fallback. Project settings are enabled for native skill discovery; the stock Claude Code system prompt/toolset is preserved. The only appended instructions identify the selected skill, uploads and file-delivery mechanism. `bypassPermissions` plus the SDK callback auto-approve ordinary tools. `AskUserQuestion` still reaches the callback, as verified by the live check.

`codex.ts` uses the [Codex app-server protocol](https://developers.openai.com/codex/app-server) over a local stdio subprocess, without an extra SDK dependency. It discovers native or npm installations, initializes the connection, checks `account/read` for ChatGPT authentication, and starts or resumes a persistent thread. It removes inherited OpenAI API credentials and endpoint overrides, forces the OpenAI provider and ChatGPT login method, and leaves authentication tokens with Codex. `codex-rpc.ts` correlates requests, bounds RPC waits, handles server requests, and closes the subprocess on Stop. Codex runs with `approvalPolicy: never` and `sandbox: danger-full-access`, matching Claude's ordinary-tool access. Messages received during a turn use `turn/steer`; if the turn finishes during steering, the message starts a new turn. There is no silent replacement of a missing saved thread.

`codex-messages.ts` maps streamed replies and reasoning summaries, command/file/MCP/dynamic tools, plans, usage, errors and turn completion into the shared events. Final snapshots do not duplicate streamed text. Dynamic tools (app-server experimental API) expose `moco_AskUserQuestion` and `moco_SendUserFile`; native `item/tool/requestUserInput` also maps through the question broker. The selected skill is supplied explicitly as a `skill` input item. Tool definitions persist with the Codex thread and restore on resume.

`messages.ts` maps SDK messages without duplicating streamed text when the full assistant message arrives. It maps TodoWrite, TaskCreate/TaskUpdate and SDK background task messages. Questions retain their original input; `QuestionBroker` resolves `canUseTool` with `updatedInput.answers` keyed by question text. Options, multi-select and free text are supported. Interrupted callbacks are denied and cleared. A question left open across app restart can be answered: its answer is saved and sent as a new user turn on the resumed session, since an in-memory callback cannot survive restart.

Codex resume requests use `excludeTurns: true`: Moco already owns its visible conversation, and full display-history hydration is deprecated for paginated Codex threads. Provider storage failures still surface as errors; Moco does not discard or replace the saved thread.

## Skills and projects

`WorkspaceStore` imports a file or folder into `<userData>/skills/<uuid>/content/`. YAML frontmatter supplies `name` and `description`; a skill name is a safe native-skill directory name. Folder imports must contain SKILL.md; symlinks/junctions are rejected. Re-importing creates an independent version. New projects default to Codex. Each project stores its provider (`claude-code` or `codex`) and copies its chosen skill version into `<workspace>/.claude/skills/<name>/` for Claude or `<workspace>/.agents/skills/<name>/` for Codex, preserving supporting files. Projects without a provider field are read as Claude Code projects, retaining their saved session IDs. `ProjectService` routes status and sessions through a provider registry and never mixes provider sessions. No example-specific logic exists in the app.

Workspaces are `<Documents>/moco/<name>-<id>/` with `uploads/` and `outbox/`. Project metadata and an append-only `conversation.jsonl` live in `<userData>/projects/<uuid>/`. Writes are serialized per project; metadata replacement is atomic. The provider session ID is saved on initialization. Missing/corrupted storage is reported, rather than silently starting another conversation. A truncated final JSONL record after a crash is ignored. Old engine data is not migrated automatically.

Attachments use native file selection, are copied under unique names into uploads/, and their absolute workspace paths accompany the user's message. The app never synthesizes content from attachments.

The example [Living Enamel skill](../examples/skills/living-enamel/SKILL.md) owns its story-first workflow and `feed` (15–20s) / `story` (45–65s) profiles, including narration timing, captions, story/publishing records and a parent analytics ledger. Its kit's `film.py qa --profile story --story story.py out/film-portrait.mp4` checks an existing encode; `python -m gilt.feedcheck out/film-portrait.mp4 --profile story --story story.py --out work/story-profile.json` runs only profile and opening-movement checks. Run with the working kit's Python from `film/`. These checks do not evaluate story quality. No application code chooses or enforces these rules, and existing pinned project copies are not upgraded automatically.

## Electron boundaries and files

- Main: `apps/desktop/src/main/index.ts`, native dialogs, lifecycle, typed request allowlist and workspace media protocol. IPC accepts only the main frame of Moco's window. Navigation, popups and browser permission requests are denied.
- Utility process: `agent-host.ts` starts `ProjectService`; this is the single conversation writer. Main correlates RPC replies and rejects pending requests if the host exits. Shutdown closes sessions and flushes writes, with a five-second fallback.
- Preload: `src/preload/index.ts` exposes `MocoAPI`; context isolation and sandboxing are on, Node integration is off. No generic shell or IPC method is exposed.
- Renderer: `App.tsx` composes the shell and dialogs. `state/` owns navigation, provider connections, theme and project attention. `features/home/`, `features/shell/`, `features/project/` and `features/files/` implement the screens described in [design.md](design.md). `conversation.ts` reconstructs visible messages from persisted events. Inter, shadcn components and neutral/blue tokens are shared across both themes. `appearance.json` stores light/dark/system and notification preferences.

Claude's in-process MCP server exposes **mcp__moco__SendUserFile({path, label?})**; Codex's dynamic tool is **moco_SendUserFile({path, label?})**. Both use the same workspace confinement and emit a persisted `file` event. External outputs can be copied into outbox/ using the agent's normal tools. Independently, the file panel scans the workspace every three seconds; it ignores hidden/dependency directories and symlinks. All ordinary files are visible in All files, and new media plus explicit deliveries in Outputs. Supported Chromium media plays inline; codec support still depends on Electron. Files appear in a drawer when the available width cannot fit both resizable panels. Text previews are bounded to 256 KB and never execute HTML or scripts.

Drafts are saved per project and reconcile uploads/sends even after navigating away. Stopping startup rejects an unsent message so its draft is retained. Project rename leaves the workspace path unchanged. Delete stops the session before removing metadata; optional folder trashing completes before metadata removal so a failed trash can be retried. Unsafe or external workspace paths are never trashed. Removing a library skill preserves each project's pinned copy.

The `moco-media://project/<id>/<relative-path>` protocol serves only allowlisted image/audio/video types, with range requests forwarded for seeking. Paths must pass lexical and realpath confinement, blocking traversal, absolute paths, Windows alternate streams and symlink/junction escapes. HTML/SVG are never served by this protocol. Open/reveal actions use the same confinement check. The agent itself is deliberately unrestricted; the renderer has no arbitrary filesystem access.

## Optional Gemini narration credentials

Agent providers remain consumer Claude Code/ChatGPT login only, with no agent-provider API key or fallback. Settings ? Narration accepts an optional user-supplied Gemini key for skill-owned narration, billed by Google to the user. Electron main stores only safeStorage-encrypted ciphertext (base64) and the non-secret voice in `<userData>/narration.json`; unavailable encryption or Linux `basic_text` refuses saving. Undecryptable data yields no key plus a re-entry status. The renderer can set/clear/check and select one of 30 prebuilt voices, but receives only status, never the saved key or suffix. Check key tests typed text before saving (or the saved key if the field is empty), using one timeout-bounded GET models request with `x-goog-api-key`, without generation.

A dedicated, unrecorded main/utility-port message updates ephemeral credentials. `ProjectService` snapshots them into session options; each provider adds `GEMINI_API_KEY` / `MOCO_GEMINI_TTS_VOICE` after its unchanged subscription-auth filter. With no Moco key, inherited shell variables stay untouched. Both long-lived providers renew their process on the next idle send after a key/voice change and resume the saved session ID; active turns, pending questions and tracked background work retain their environment. Codex retains its existing `danger-full-access` network/filesystem policy. Custom Codex shell environment filters or shell startup files can still remove/override variables; Moco does not weaken those policies. Credentials never go in Moco's prompts, metadata, workspace or logs; agent-authored tool/text output is persisted as usual, so an agent printing its environment can expose it in its own output and transcript. Main currently pipes utility stdout/stderr to its parent; Codex drains its own stderr. Do not print secrets.

A saved key makes Gemini available without replacing an explicit project voice. Ink-history offers Gemini alongside Zonos/Kokoro when a key is saved; a saved Gemini preference stays visible but disabled when its key is removed. ?Use story default? adds only a short availability preference to the agent message; explicit local choices suppress it. Moco supplies no synthesis workflow. The skill helpers read only `GEMINI_API_KEY`, avoiding the Google SDK's `GOOGLE_API_KEY` precedence; voice is explicit argument, then `MOCO_GEMINI_TTS_VOICE`, then Charon. Helpers send header credentials, keep style separate from spoken words, disable redirects, use a 30-second timeout and at most one transient retry, and accept WAV or wrap raw PCM. The current [speech guide](https://ai.google.dev/gemini-api/docs/speech-generation) demonstrates `gemini-3.8-flash-tts` with the Interactions API, style annotations, and unary WAV output. Existing project skill copies are pinned: import the updated skill folder and create a new project to receive the new kit; existing films are never upgraded or regenerated automatically.

## Build and verification

The utility host and agent sources use erasable TypeScript. Dev runs them directly. Packaging preserves their directory relationship under `runtime/`, with production dependencies in the app's node_modules and ASAR disabled so Node can strip source types outside node_modules. SDK native CLI downloads are omitted: Moco uses separately installed Claude Code or Codex. Electron build/icons/installer targets and the UI component library remain. The independent website and pre-existing local user media/caches remain untouched.

`pnpm install`, `pnpm typecheck`, `pnpm test`; `pnpm --filter @moco/desktop build`, then `pnpm test:desktop`. Tests cover skill parsing/copying, legacy and provider-specific project persistence, provider routing, uploads, SDK and Codex event mapping, question round-trips/cancellation, hand-off and path confinement. A fake app-server tests actual subprocess/RPC behavior without AI calls, including authentication, resume, steering races, stopping and crashes. The Electron smoke check uses Codex projects, checks that connection results never switch the default to Claude, and verifies provider, skill, theme and draft persistence across restart. It runs against either the production build or `MOCO_SMOKE_EXEC` for a packaged executable. See [UI verification](ui-qa.md) for results and remaining release checks. `pnpm agent:check --codex` checks the real installed Codex and ChatGPT login without starting an inference turn. The opt-in `pnpm agent:check --live` (Claude) or `pnpm agent:check --codex --live` exercises the actual installed provider with the reference skill, stops at intake and cleans its temporary workspace. The fixture is instructions only: the original attachment did not supply its kit.
